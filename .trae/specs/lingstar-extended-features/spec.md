# 梦语 · 传讯 扩展功能 - 产品需求规格 (PRD)

## 概述
- **摘要**: 在现有单文件 HTML 聊天应用 (`/workspace/lingstar.html`) 中，重做界面三大板块（头像位置、许愿树、留言板），新增 4 套以上精致主题，并构建三类「小游戏」互动功能：猜拳奖惩、涂鸦板、你画我猜。所有修改都在浏览器单文件内完成，无后端依赖，无外部服务器。
- **目的**:
  1. 满足用户对界面质感的要求：头像在气泡外、许愿树的发光立体星星（栽在树形底板上）、留言板的书页纹理+便利贴形状。
  2. 提供 6 套以上色调统一的主题，切换时横扫侧栏/留言板/许愿树/弹窗/按钮/输入焦点环。
  3. 新增文字类小游戏分组（猜拳、涂鸦、你画我猜），以独立区域/独立侧栏项/独立弹窗子板块区分，与其他功能（字卡、拍一拍、表情包、通话）有清晰边界。
- **目标用户**: 梦女用户（自娱场景：梦女 ↔ 梦角）。

## 目标
- G1：头像完全在消息气泡外（梦角左侧、梦女右侧），头像与气泡有合适间距和阴影。
- G2：许愿树底板是真实树形布局（树干 + 树冠/树叶区域），未抽取时树叶区无星，抽取后随机位置长出发光立体五角星，色彩与主题联动。
- G3：留言板底板为书页纹理（横格线/网格/空白可切换），便签使用便利贴形状（折叠角），多色彩缤纷，不使用信封式外观。
- G4：至少 6 套中文命名主题，切换时 CSS 变量同步覆盖侧栏/留言板/许愿树/弹窗头/按钮/输入焦点环，没有板块颜色「穿色」。
- G5：猜拳奖惩小游戏：两种玩法模式（赢方制定奖惩 vs 梦角制定奖惩）、跨角色切换带确认弹窗 + 回答同步告知梦角、历史记录 + 胜负次数统计、永久保存。
- G6：涂鸦板功能：梦女梦角各自可绘制（Canvas），保存每次涂鸦为一张 PNG/base64 记录，可回看，可删除，永久保存。
- G7：你画我猜游戏：两种模式（自由画 / 话题限定画），跨角色切换模式时确认弹窗 + 结果同步告知梦角；话题库：植物/动物/水果/景物/食物/事物（可用户自扩展）；梦女梦角各自出题/画；答案与结果记录可回看。
- G8：当留言板「回复写入聊天」或许愿树「回复写入聊天」被勾选时，聊天消息会附带原留言便签或原星星的正文内容的引用片段。
- G9：整个应用无后端依赖，所有数据（外观、留言、许愿、猜拳记录、涂鸦、你画我猜记录）保存在 localStorage。
- G10：主题数量不限制 6 套，系统可扩展（回答用户 "主题就只能六个吗？" 的疑问：不是，系统支持通过编辑器 + 保存方案持久化 + 代码中后续新增更多主题）。

## 非目标
- 不引入后端/网络存储
- 不引入 ES modules / 打包工具 / 外部依赖库（除了内置 Canvas API）
- 不做移动端 UI 单独重绘（响应式保持当前级别即可）
- 不做多人实时协作（梦角回复一律本地模拟）
- 不在本次范围中重写字卡/表情包/拍一拍/通话/日历/日记/信封等已有功能

## 背景与上下文
- 当前代码状态：从 `lingstar.docx` 中按 Word 段落还原提取出的 HTML 文件 `/workspace/lingstar.html`，大小 106,603 字节，包含基础聊天 + 字卡/表情包/拍一拍/通话/昵称头像设置/主题色简易色板。
- 经核查：当前文件中 **缺失** 以下上一回合约定的功能，需要在本回合补齐：
  - 头像在气泡外的 CSS 结构与 JS 包装
  - 许愿树星星 clip-path 五角星 + 径向渐变
  - THEME_PRESETS 与 applyThemeVariables 30+ 变量机制
  - 留言板 / 许愿树 主功能板块（弹窗、抽取按钮、话语库、每日 5 限、回复表单 + "回复发送到聊天" 勾选框 + localStorage 保存）
- 上一回合提供的 Handoff 描述了这些功能的正确参考实现样式，本次实现将对齐这些结构，并在此之上继续建设小游戏功能。
- 回答用户疑问：「主题就只能六个吗？」→ 不会，6 套是启动预设，主题系统本身是开放式的：设置面板中的自定义编辑器（颜色输入 + 滑块）+「📁 主题方案 → ➕ 保存当前」可以让用户保存自己的主题；后续代码中也可以不断追加新的 THEME_PRESETS 条目。

## 功能性需求

### FR-0 代码健康与前置基础（补齐缺失功能 + 语法修复）
- FR-0.1 所有功能入口在浏览器 `node --check` 通过的脚本下运行，Console 0 Error。
- FR-0.2 侧栏功能面板中必须存在以下 7+ 个独立入口：📜 字卡 · 😊 表情包 · 👋 拍一拍 · 📅 日历 · 📖 心情日记 · ✉️ 信封 · 📋 留言板 · 🌳 许愿树 · 🎮 小游戏（新）· 🎨 涂鸦板（新，可并入小游戏）· 🖌️ 你画我猜（新）
- FR-0.3 localStorage 有单一命名空间入口 `dream_appearance` + `dream_games`，完整保存外观与所有游戏数据，可导出/导入。

### FR-1 头像位置（气泡外）
- FR-1.1 每一条消息的 DOM 结构为：`.message` 作为一行容器（display:flex / align-items:flex-end / gap:8px / max-width:88%），直接子元素是 `.msg-avatar` + `.msg-bubble`。
- FR-1.2 梦角消息（`.message.system`）：avatar order=0（左边），气泡在右；justify-content 为 flex-start；梦角不显示 avatar 的场景（如 pat 通知）有独立 class 处理。
- FR-1.3 梦女消息（`.message.user`）：avatar order=2（右边），气泡在左；justify-content 为 flex-end；点赞/收藏⭐等按钮挂在 `.msg-bubble` 上，不脱离气泡。
- FR-1.4 气泡形状（sharp / round）的小尾巴伪元素作用在 `.message.user .msg-bubble::after` 和 `.message.system .msg-bubble::after` 上，不再指向 `.message`。
- FR-1.5 avatar 有白边与阴影，尺寸 30px 圆形，文字颜色 fallback 使用 梦女头像🌸/梦角头像🌙，支持用户自定义图片与 emoji。

### FR-2 许愿树美化（树形底板 + 随机位置星星 + 发光立体）
- FR-2.1 许愿树弹窗有明显的树形视觉：中央下方显示树干 emoji（🌳/🎄 或 SVG 简化树干）+ 顶部/四周椭圆的 "树叶" 区域（半透明柔和色块，模拟树冠），背景渐变使用 `--wish-tree-bg` 变量，随主题变。
- FR-2.2 **抽取前初始状态**：树叶区无任何星星；只有 🌳 树干 + 空树叶画布。
- FR-2.3 点击「✨ 摘取星星」后：随机颜色（黄/粉/蓝/红/绿/紫）、随机大小、随机位置（仅落在树冠椭圆区域内）、随机旋转（±15°）生成一颗五角星，写入许愿树记录。
- FR-2.4 星星形态：clip-path polygon(50% 0%, 61% 35%, 98% 35%, 68% 57%, 79% 91%, 50% 70%, 21% 91%, 32% 57%, 2% 35%, 39% 35%)，加上发光 box-shadow（外层柔光，用 drop-shadow + box-shadow），内部使用 radial-gradient 做立体高光（中心偏浅白）。
- FR-2.5 每日最多 5 颗星，超出后「摘取星星」按钮禁用并提示（与前版约定一致：cap=5/天）。
- FR-2.6 每颗星星可点击打开详情：原愿望内容 + 梦角回复 + 回复时间；详情使用 `--wish-detail-bg` 背景变量。
- FR-2.7 有独立的「📝 愿望」话语管理弹窗（6 色各一套短语库），以及「📜 历史」弹窗查看所有已摘星星及状态（已回复/未读）。
- FR-2.8 回复表单有"回复写入聊天"勾选框；勾选后，写入聊天时**同时附带原星星的引用内容**（G8）。
- FR-2.9 图例 indicator 使用 mini 五角星而非圆点。

### FR-3 留言板美化（书页纹理底板 + 便利贴形状）
- FR-3.1 留言板弹窗内容区背景（`--board-bg`）为"书页纹理"，支持三选一形态：横格线 / 作文网格 / 空白页。切换控件在弹窗工具栏，记忆用户偏好。
- FR-3.2 小纸条为**便利贴形状**（四角略微圆润，右上角有折角效果），不使用信封/信件外形；使用渐变颜色与主题一致（黄粉蓝绿紫橙…不同色彩池交替奇偶位置）；使用 CSS transform rotate(±1~3deg) 做"贴在桌面上"的视觉错落。
- FR-3.3 颜色池与主题联动：`--board-note-bg` 与 `--board-note-bg-alt` 两套变量分别为奇数/偶数便签的主色。
- FR-3.4 每条便签支持：未读小红点、便签上显示 emoji 头（📋 + 颜色编码标签）、时间戳、是否有回复的标记（💬 回复）。
- FR-3.5 点击便签展开详情（`.board-detail { --board-detail-bg }`）：原留言 + 回复列表 + 底部回复表单（多行文本 + 发送按钮）。
- FR-3.6 每日最多 5 条留言；有「📝 话语」管理弹窗与「📜 历史」记录回看。
- FR-3.7 回复表单有"回复写入聊天"勾选框；勾选后写入聊天时**同时附带原留言的引用内容**（G8）。

### FR-4 主题统一体系
- FR-4.1 在 :root 中声明不少于 30 个语义化 CSS 变量（见前版 handoff：`--side-panel-bg`/`--board-*`/`--wish-tree-bg`/`--btn-primary-bg`/`--modal-header-border`/`--input-focus-ring`/`--shadow-card` 等）。
- FR-4.2 `THEME_PRESETS` 至少 6 套中文命名的精致配色：🌙 月落紫樱 / 🌊 夏日海盐 / ☕ 焦糖摩卡 / 🌲 森林薄雾 / 🌸 樱花乳酪 / ✦ 星夜琥珀；每套配色都填写了全部 30+ 语义化变量，确保切换时横扫每一块。
- FR-4.3 `applyThemeVariables()` 将 JSON 中的每一个 key 映射到 CSS `setProperty`，包括基础颜色 + 透明度系列 + 板块专属变量。
- FR-4.4 `getCurrentThemeVars()` 从 computedStyle 中反读所有变量，经 `saveCurrentThemeToStorage` 写入 localStorage，可恢复。
- FR-4.5 快捷换肤 swatches：4 列布局，6 颗渐变预览色 + 自定义 1 颗（共 7 格），每格鼠标悬停显示中文 tooltip（如 🌙 月落紫樱）。
- FR-4.6 自定义：强调色/强调色2/两套气泡/聊天背景/页面背景/弹窗背景/遮罩色/主副文字，共 9 个颜色输入 + 8 个半透明/模糊滑杆，即时同步到变量。
- FR-4.7 「📁 主题方案 → ➕ 保存当前」：一键将当前配色保存到 savedThemePresets，可快速切换/覆盖/删除，实现主题数量不封顶（回答 "主题只能六个吗？"）。
- FR-4.8 以下组件都必须使用语义变量才能切换主题：侧栏背景与按钮、modal-content 阴影、modal-header 分隔线、primary 按钮的背景与文字、留言板内容区、便签双色、便签详情背景、许愿树背景与星星详情背景、输入 focus ring、side-header 的底部分隔线。
- FR-4.9 `btn-primary-mod` 必须有 hover（Y 抬升 1px + 亮度 + shadow 加深）/active（缩放 0.97）动效，色彩随 `--btn-primary-bg/--btn-primary-text` 变。

### FR-5 小游戏分组 + 侧栏分组入口
- FR-5.1 侧栏/底部功能中出现全新大分组「🎮 小游戏」，与「字卡/表情包/拍一拍」同级呈现；内部子分组：
  - ✊ 猜拳奖惩
  - 🎨 涂鸦板
  - 🖌️ 你画我猜
- FR-5.2 小游戏子分组与其他功能的视觉区分度：分组标题有独立的背景色块与 emoji 前缀（🎮）、分组内部有一条独立的分隔线、分组的子卡片尺寸略小以区分。
- FR-5.3 每一个小游戏都以**独立的大弹窗**呈现（sub-modal，覆盖在设置弹窗之上），ESC 可关闭、右上角 ✕ 可关闭。
- FR-5.4 每一个小游戏界面都以**文字 + 控件**形式呈现（不使用图像化花哨卡片，符合用户所说"文字形式显示小游戏"）。

### FR-6 猜拳奖惩小游戏
- FR-6.1 主界面：顶部角色切换器（🎀 梦女视角 / 🌙 梦角视角），中间两块选择区（✊ 石头 / ✌️ 剪刀 / ✋ 布），底部显示结果区，再底部历史记录 + 统计板。
- FR-6.2 **两种玩法模式**（顶部有模式切换）：
  - 模式 A：「赢方制定奖惩」— 任何一方赢了都可以制定奖励或惩罚内容。
  - 模式 B：「梦角统一制定奖惩」— 无论输赢，奖惩内容都由梦角输入（梦角输入框在模式 B 下开启）。
- FR-6.3 **角色切换确认弹窗**：当用户尝试从梦女切换到"梦角想要玩双方奖惩"（即 梦角 → 模式 A）时，弹出 confirm 风格弹窗：
  > 🌙 **梦角想要开启「双方都可制定奖惩」模式**，是否同意？<br>
  > [同意]  [拒绝]
  - 用户点击「同意」或「拒绝」后，回答会以系统消息的形式同步到主聊天区中，告知梦角（如：「📝 梦女同意开启双方奖惩模式 🎉」或「📝 梦女暂时不想开启双方奖惩模式 😢"）。
- FR-6.4 出拳流程：梦女先选 → 保存到当前回合；界面显示「等待梦角出拳」；0.8~2s 后梦角随机出拳 → 比对 → 显示胜方（梦女/梦角/平局）。
- FR-6.5 奖惩输入：获胜方（或模式 B 下永远是梦角输入框）弹出输入奖惩内容的表单（奖励/惩罚类型切换 + 多行文本），写入本轮结果。
- FR-6.6 永久记录：每一场回合（出拳梦女、出拳梦角、胜者、模式、奖惩内容、时间戳）保存到 `dream_games.rps_history[]`；历史可按时间倒序回看、可搜索、可清空。
- FR-6.7 输赢统计：看板显示梦女胜 N / 梦角胜 M / 平 D / 总场 T / 胜率 %。分别显示模式 A/B 的独立统计。
- FR-6.8 平局：不输入奖惩，直接写入"平局"标记，可选择重赛。
- FR-6.9 导出：历史记录可一键以 JSON 下载，支持 JSON 导入（合并/覆盖策略）。

### FR-7 涂鸦板
- FR-7.1 主界面：顶部角色切换器（梦女 / 梦角），中央大 Canvas（800×500 或视窗自适应），工具栏：画笔大小（1/2/4/8/16/24px）、画笔颜色（调色板 + 任意色）、画笔类型（铅笔 / 马克笔 / 橡皮擦）、撤销 / 重做 / 清空 / 保存。
- FR-7.2 支持绘制：纯前端 Canvas 2D 实现（不依赖外部库）。撤销栈深度 50 步。
- FR-7.3 保存：点击保存后，将 Canvas 转为 PNG dataURL，连同 `author`（梦女/梦角）、时间戳、尺寸、标题（可选）一起，保存到 `dream_games.doodles[]`，最大 50 张存档，超出时覆盖最旧。
- FR-7.4 回看：「📜 画廊」以 4 列网格显示每张涂鸦缩略图；点击打开大图（含作者/时间/标题），可删除、可下载为 PNG 文件，可发送到主聊天区。
- FR-7.5 发送到聊天：涂鸦查看页有「💬 发送到聊天」按钮，点击后在主聊天区插入一条画布消息，显示缩略图 + 可点击放大预览。
- FR-7.6 主题联动：Canvas 背景色随 `--wish-detail-bg`（浅色系），工具栏按钮使用 `--btn-primary-bg/--btn-primary-text`。
- FR-7.7 支持触摸事件（触屏绘画）以及鼠标事件。

### FR-8 你画我猜
- FR-8.1 主界面：顶部角色切换器（梦女 / 梦角） + **模式切换器**（自由话题 / 话题限定）。
- FR-8.2 **两种玩法模式**：
  - 模式 A「自由画」：出题方输入任意文字作为题目 → 绘画方根据题画 → 猜题方在输入框中猜测文字；命中即胜利；有倒计时（可选 60/90/120s）。
  - 模式 B「话题限定画」：先从话题分类（🌱植物 / 🐾 动物 / 🍎 水果 / 🏞 景物 / 🍜 食物 / 🧸 事物）中随机抽一个分类，再从该分类的词库随机抽一个词作为题目，流程同上。
- FR-8.3 话题库内置基础条目，用户可以在「话题管理」中对每个分类增删词；分类本身也可增加（如 🏠 建筑、🎬 电影、⚽ 运动）。
- FR-8.4 **跨角色/跨模式确认弹窗**：当用户处于「梦角」视角，想从话题限定切到「自由画」模式时，弹出弹窗：
  > 🌙 **梦角想要玩「无话题自由画」模式**，是否同意？<br>
  > [同意]  [拒绝]
  用户点击「同意」或「拒绝」后，以系统消息的形式同步到主聊天区告知梦角（如「📝 梦女同意开启自由画你画我猜 ✨」或「📝 梦女想继续玩话题限定的你画我猜 😅」）。
- FR-8.5 回合流程：
  1. 点击「开启新一轮」→ 选定出题方（梦女 or 梦角）→ 出题 → 倒计时开始
  2. 出题者切换到画画界面（Canvas 复用涂鸦板的精简版：画笔/橡皮/撤销/清空），猜题者只能看到猜输入框 + 倒计时（看不到画图？—— 根据"双方互动进行绘画"，猜题者也可以看到画作）。
  3. 猜题方输入文字提交；与答案匹配（忽略大小写、去空格、支持同义词）即命中；命中时显示「答对了🎉」，回合结束，双方积分+1，记录本轮。
  4. 如果倒计时走完，揭晓答案，显示"时间到啦～本轮答案：XXX"。
- FR-8.6 角色可以在一局中交换：下一局出题方自动轮换（梦女→梦角→梦女…）。
- FR-8.7 永久记录：`dream_games.draw_guess_history[]` 保存每轮（出题者、画画者、猜题者、模式、话题分类、题目、答案、是否命中、耗时、画图 dataURL 缩略图、时间戳）。历史可回看，可删除，可导出。
- FR-8.8 积分板：梦女答题正确数 / 梦角答题正确数 / 总轮数。显示模式 A/B 独立统计。
- FR-8.9 你画我猜匹配成功时以系统消息自动写入主聊天区（可开关）：「🖌️ 你画我猜新纪录：[梦女] 出题「XXX」，[梦角] 画出后 [梦女] 猜对啦！🎉」。

### FR-9 留言/许愿回复 → 聊天附带原内容
- FR-9.1 留言板回复表单：当勾选「回复发送到聊天界面」时，发送到聊天区的梦角消息体需包含：
  > ——————— 📋 原留言 ———————<br>
  > {原留言便签的完整正文内容}<br>
  > ——————— 💬 梦角回复 ———————<br>
  > {当前回复内容}<br>
  使用引用样式的 `msg-quote`（上方有装饰条，左侧有色竖条）。
- FR-9.2 许愿树回复表单：同理，消息体包含：
  > ——————— 🌟 原愿望 ———————<br>
  > {原星星色彩标签 + 愿望分类 + 完整正文}<br>
  > ——————— 💬 梦角回复 ———————<br>
  > {当前回复内容}<br>
- FR-9.3 若勾选框未被勾选，聊天区不写入任何内容（保持前版行为）。
- FR-9.4 附带原内容的引用部分使用 CSS class `bd-quote-block` / `ws-quote-block`（分别为留言/许愿引用），颜色随主题的 `--accent-soft / --accent` 变化。

## 非功能性需求

- **NFR-1（性能）**：单页加载 ≤ 1.5s（本地 http.server，Chrome），Canvas 绘制 60fps，小游戏不卡聊天主流程。
- **NFR-2（可维护性）**：所有 CSS 规则通过语义化变量驱动；主题切换不允许出现硬编码。
- **NFR-3（稳定性）**：刷新后所有保存的外观、留言/许愿、猜拳、涂鸦、你画我猜数据依然完整（localStorage 持久化）。
- **NFR-4（兼容性）**：Chrome/Edge 最新版可用；移动端 Safari/WebView 可使用。
- **NFR-5（可扩展性）**：话题库、主题库、小游戏模式枚举都有独立 JS 常量数组方便后续扩充。

## 约束
- **技术**：全部为单文件 HTML（`<style>` + 一段 IIFE `<script>`）；不得加入任何外部 CDN 或 npm 依赖。
- **业务**：所有游戏回合判定为本地脚本模拟，不涉及真实双方网络对战。
- **兼容性**：`lingstar.html` 可直接以 `file://` 协议双击打开，同时也可在 `python -m http.server 8765` 下运行。

## 假设
- 梦角出拳随机分布均匀（石头/剪刀/布 各 1/3）。
- 梦角画画（你画我猜）本地不生成画面；由梦女代替梦角画画（或梦角回合也让用户自行操作作为梦角代入）。**交互假设**：两类角色都是本地用户扮演（单机自娱）。
- 猜拳奖惩内容、涂鸦板、你画我猜的画图缩略图都以 base64 存 localStorage，体积较大时会有限量（涂鸦最大 50 张、你画我猜历史最大 200 条）。

## 验收标准 (Acceptance Criteria)

### AC-0 代码检查通过 + 所有入口可用
- **Type**: `rule`
- **Given**: 已部署到 `python -m http.server 8765`
- **When**: 打开 `http://localhost:8765/lingstar.html`，查看 Console
- **Then**: Console 0 Error；侧栏显示 字卡 / 表情包 / 拍一拍 / 日历 / 心情日记 / 信封 / 留言板 / 许愿树 / 🎮 小游戏（子三项 ✊✋✌️ / 🎨 / 🖌️）
- **Pass Condition**: 无 JS 错误且入口齐全
- **Evidence**: `browser_console_messages` + snapshot 截图

### AC-1 头像在气泡外（结构/视觉）
- **Type**: `rule`
- **Given**: 发送任意一条消息后等待梦角回复
- **When**: 检查 DOM 结构 + 计算布局
- **Then**: 对于梦女消息 `.message.user > .msg-avatar` 作为直接子节点存在且 `order != 0`（右侧），`.message.user` justify-content = "flex-end"；对于梦角消息 `.message.system > .msg-avatar` order=0（左侧），justify-content = "flex-start"；并且 `.msg-bubble > .msg-avatar` 不应该存在（头像不在气泡内部）。
- **Pass Condition**: 结构检查全部正确
- **Evidence**: `browser_evaluate` 抽取结构 JSON 记录

### AC-2 许愿树树形底板 + 随机长星 + 发光立体
- **Type**: `rule`
- **Given**: 打开许愿树弹窗（初始状态）
- **When**: 初始 → 点击「摘取星星」多次
- **Then**: ①初始态树冠画布中无 `.star-item`；②每次「摘取星星」后树冠内（椭圆范围）增加一个 `.star-item`，`top/left` 坐标都在树冠椭圆中；③每个 star-item 都有 `clip-path: polygon(...)`（5 角星形状）和发光 box-shadow/drop-shadow；④星星的数量 ≤ 5（每日上限），第 6 次开始按钮 disabled。
- **Pass Condition**: ①②③④ 全部满足
- **Evidence**: 截图 + evaluate 提取 star-item 坐标数组、clip-path 文本、count 计数。

### AC-3 留言板书页纹理 + 便利贴形状
- **Type**: `rule`
- **Given**: 打开留言板弹窗
- **When**: 初始（默认横格）→ 切换到网格、空白
- **Then**: ①留言板内容区有书页 SVG 或 CSS 背景（横格/网格/空白三态可切换）；②所有 `.board-note` 便利贴都有右上角折角效果（伪元素 clip-path 或 border-triangle 形成折角），不使用信封形态；③ 便签颜色按奇偶取两套不同的 `--board-note-bg`/`alt` 渐变；④ 便签各自有 ±1~3° rotate。
- **Pass Condition**: 全部满足
- **Evidence**: evaluate 提取每个 note 的 rotate/background/border-radius（折角）属性 + 三种书页背景切换截图。

### AC-4 6+ 套主题统一切换
- **Type**: `rule`
- **Given**: 打开设置 → 主题外观面板
- **When**: 依次点击 6 个快捷换肤
- **Then**: 每一套主题切换后，`document.documentElement.style` 中的 `--accent / --wish-tree-bg / --side-panel-bg / --board-note-bg / --btn-primary-bg / --modal-header-border / --input-focus-ring` 7 项关键变量都等于 THEME_PRESETS 中对应值。

- **Evidence**: `browser_evaluate` 输出 6×7 的 JSON 表。

### AC-5 主题数量不封顶
- **Type**: `rule`

### AC-6 猜拳奖惩两种模式 + 切换确认弹窗 + 记录/统计

### AC-10 色调统一视觉和谐
- **Type**: `rubric`
- **Dimension**: 6 套主题下各版块色彩的整体协调度
- **Scale**: 1-5
- **Anchors**:
  - 1 = 至少有两套主题在留言板/许愿树/弹窗颜色出现明显撞色或对比度过强
  - 3 = 6 套主题基本不穿色，按钮/输入环都变，但便签/星星色偶尔会和背景混

- **Evidence**: 每套主题对应一张界面截图（侧栏 + 留言板 + 许愿树 + 设置主面板拼接）并在评审时人工打分。

### AC-11 小游戏分组视觉区分度
- **Type**: `rubric`

- **Scale**: 1-5
- **Anchors**:

  - 3 = 有 🎮 标题前缀，但色块大小/样式与其他项相同

- **Evidence**: 侧栏/底部功能截图。
